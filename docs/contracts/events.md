# Подія звіту сесії — `rover.session.v1`

Один звіт = одна сесія ровера. Це єдиний тип даних, який ровер надсилає. Нижче описано **поточний** формат (прошивка фази 8) і, окремо, **заплановані** доповнення.

## Доставка

| Параметр | Значення |
|---|---|
| Топік | `rover/<mac>/session`; `<mac>` — 12 hex-символів нижнім регістром |
| Гарантія | QoS 1 («принаймні раз»), `retain` вимкнено |
| Формат | один JSON, компактний, ≤ 1024 байти, UTF-8 |
| Порядок | від найстаршого невідправленого; на порядок отримання покладатись не можна, лише на `seq` |
| Повтор | якщо підтвердження брокера не дійшло, ровер надішле той самий звіт знову при наступній спробі → **дублікати неминучі** |
| Зворотний канал | немає: ровер нічого не підписує й не отримує |

## Ідентифікатор для дедублікації

**Вже є:** пара (`mac`, `seq`). `seq` — номер сесії, зростає на 1 для кожної сесії й не повторюється навіть після перезапуску плати (зберігається у флеші). Повторно надісланий звіт має ті самі `mac` і `seq` і побайтово той самий вміст. Унікальний ключ запису — (`mac`, `seq`); дубль ігнорувати.

Додаткового ідентифікатора не потрібно. Наслідок: **пропуск у `seq` для одного `mac` означає втрачену сесію** (ровер тримає лише 2 недоставлені звіти, третій витісняє найстарший).

## Дата й час: чого немає

На ровері **немає годинника** і синхронізації часу. Подія не містить дати чи часу створення. Єдина мітка — `duration_ms` (тривалість сесії). Сервер ставить власний час отримання (`received_at`); це верхня межа часу сесії, не її час: звіт може прийти через години чи дні після виїзду.

### Заплановане доповнення (не реалізовано, потребує зміни прошивки)

Щоб відновлювати час створення, пропонується додати (адитивно, схема лишається сумісною):

| Поле | Зміст |
|---|---|
| `boot_id` | лічильник запусків плати (у флеші) |
| `end_uptime_ms` | час від старту плати до кінця сесії, мс |
| `sent_uptime_ms` | час від старту плати до відправки цього звіту, мс |
| `sent_at_utc` | час відправки (UTC, ISO 8601), якщо в цю спробу вдалось синхронізувати час; інакше `null` |

Відновлення: якщо `sent_at_utc` є і звіт створено й надіслано в одному запуску (`boot_id` збігається з поточним), то `created_at ≈ sent_at_utc − (sent_uptime_ms − end_uptime_ms)`. Інакше — лише `received_at` як верхня межа. Поки поля не додано, дашборд має працювати з `received_at` і не вигадувати час сесії.

## Поля

Відсутнє значення — явний `null`, а не нуль. Одиниці — в назві поля.

### Ідентифікація

| Поле | Тип | Значення |
|---|---|---|
| `event` | string | завжди `rover.session.v1` |
| `schema_version` | int | завжди 1 |
| `seq` | int | номер сесії (див. вище) |
| `mac` | string | MAC плати, 12 hex, нижній регістр; ідентифікує ровер |
| `fw.version` | string | версія прошивки з образу; `unknown`, якщо немає |
| `fw.git` | string | git-хеш образу; `unknown`, якщо збірка його не дала |
| `fw.dirty` | bool | збірка з незафіксованими змінами; **поле відсутнє**, якщо збірка цього не повідомила |
| `fw.idf` | string | версія ESP-IDF |

### Сесія

Сесія починається, коли ровер озброюється (стан ARMED), і закінчується при виході в роззброєний стан чи аварійну зупинку. Перехід між ARMED і утриманням перед перешкодою сесію не перериває. Сесія без жодного руху теж звітується.

| Поле | Тип | Значення |
|---|---|---|
| `duration_ms` | int | тривалість від початку до кінця сесії, мс |
| `end_reason` | string | `disarm` — роззброєння (тумблером чи консоллю); `failsafe_link_lost` — зникли кадри пульта довше за 0.5 с; `failsafe_voltage` — напруга акумулятора нижче порога відсічки 6.0 В |

### Напруга акумулятора (2S, мВ)

| Поле | Тип | Значення |
|---|---|---|
| `voltage_start_mv` | int \| null | на початку сесії |
| `voltage_end_mv` | int \| null | наприкінці; для `failsafe_voltage` — остання напруга **перед** відсічкою |
| `voltage_min_mv` | int \| null | мінімум за сесію (просадка під навантаженням) |

`null`, якщо вимірювання напруги було відсутнє чи застаріле в потрібний момент. Практична межа: нижче 6000 мВ мотори не запускаються.

### Утримання перед перешкодою (`holds`)

Ровер зупиняється перед перешкодою, коли далекоміри бачать її ближче за поріг (зараз 190 мм), і лишається в стані «утримання», доки сектор не звільниться. Є два сектори: передній (три датчики) і задній (один).

| Поле | Тип | Значення |
|---|---|---|
| `holds.count` | int | скільки разів ровер увійшов в утримання (0, якщо не було) |
| `holds.total_ms` | int | сумарний час у утриманні, мс |
| `holds.min_mm` | int \| null | найменша відстань, зафіксована **на вході** в утримання; `null`, якщо утримань не було |
| `holds.min_sensor` | string \| null | датчик, що дав `min_mm` |
| `holds.by_sensor.*` | int | для кожного датчика: у скількох утриманнях він на вході був нижче порога |
| `tof_control_off_ms` | int | скільки мс за сесію був **вимкнений** контроль перешкод (тумблер на пульті). Відрізняє «перешкод не було» від «захист був вимкнений» |

Датчики: `left_front` (ліво-вперед), `front` (прямо), `right_front` (право-вперед), `rear` (ззаду). Несправний датчик у лічильники не потрапляє. Утримання при вимкненому контролі не виникають.

### Рух

Час руху — час, коли хоча б один борт отримував ненульову потужність. Штовхання вручну й рух накатом не рахуються.

| Поле | Тип | Значення |
|---|---|---|
| `moving_ms` | int | час руху, мс (0 — не їхав) |
| `distance_cm` | int \| null | пробіг, см: сума зміщень центру ровера лише на інтервалах руху; розворот на місці пробігу не додає. `null`, якщо не було жодного доступного енкодера. Точність ≈ ±5 %; проковзування не враховано |
| `speed.left_avg_rpm`, `speed.right_avg_rpm` | number \| null | середня швидкість борту за час руху, об/хв колеса (модуль) |
| `speed.left_peak_rpm`, `speed.right_peak_rpm` | number \| null | пікова швидкість борту, об/хв |
| `speed.imbalance_pct` | number \| null | різниця бортів у %: (лівий − правий) / півсума; плюс — лівий швидший. Лише за інтервали прямої їзди (задані значення бортів однакові й ненульові). `null`, якщо прямої ділянки не було чи в борта немає енкодера. Діагностична метрика, відома особливість: один борт повільніший |
| `encoders.left`, `encoders.right` | bool | чи був у борту доступний енкодер хоч раз за сесію. `false` пояснює `null` у швидкостях цього борту й те, що пробіг рахувався за одним бортом |

Діаметр колеса 44 мм, швидкість у об/хв колеса (лінійну швидкість у м/с дашборд може обчислити: об/хв × 0.1382 м / 60).

## Приклад

```json
{"event":"rover.session.v1","schema_version":1,"seq":42,"duration_ms":187000,"end_reason":"disarm",
 "voltage_start_mv":8240,"voltage_end_mv":7710,"voltage_min_mv":7480,
 "holds":{"count":3,"total_ms":4200,"min_mm":95,"min_sensor":"front",
          "by_sensor":{"left_front":1,"front":3,"right_front":2,"rear":0}},
 "tof_control_off_ms":0,"distance_cm":5320,"moving_ms":142000,
 "speed":{"left_avg_rpm":88.4,"left_peak_rpm":141.0,"right_avg_rpm":84.1,"right_peak_rpm":138.5,"imbalance_pct":5.0},
 "encoders":{"left":true,"right":true},
 "fw":{"version":"b667905","git":"b667905","idf":"v6.1"},"mac":"aabbccddeeff"}
```

Звіт з відсутніми даними (аварія по напрузі, енкодерів немає): `distance_cm`, `holds.min_mm`, `holds.min_sensor`, усі `speed.*` — `null`, `encoders` — `false`.

## Правила для споживача

- Невідомі поля ігнорувати (еволюція без зламу); `schema_version` змінюється лише при несумісній зміні.
- `null` зберігати як відсутнє значення, не підставляти нуль.
- Підтверджувати повідомлення брокеру лише після успішного запису.
- Паролів і SSID у події немає й не буде.
