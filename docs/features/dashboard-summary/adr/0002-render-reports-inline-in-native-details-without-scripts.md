# 0002 — Вбудовувати повні звіти в сторінку й розгортати їх нативним details без скриптів

- **Status:** Accepted
- **Date:** 2026-10-24
- **Deciders:** 12romis (власник), Claude (design)

## Context

Власник розгортає рядок виїзду до повного звіту «так, як його надіслав ровер» (spec AC-05, US-03; `ux-flows.md` SCR-02). `ux-flows` залишив `design` вибір: або звіти всіх виїздів віддаються разом зі сторінкою, або кожен підвантажується за натисканням. Це також перший екран проєкту, тож його підхід стає прецедентом для кроків 4–8. Вибір SSR уже зроблено фундаментальним ADR-0001 (Jinja2, без збірки фронтенду); тут рішення про те, як віддавати звіт.

## Decision drivers

- Сторінка відкривається без зовнішніх вузлів і з суворим CSP; поверхня для XSS мінімальна (spec §6, §6.1).
- Мобільна розкладка: одна колонка, ціль дотику не менша за палець; розгортання на місці, не модальне (spec AC-10, `ux-flows.md`).
- Звіт одного виїзду ≤ 1024 байти за контрактом, обсяг розрахунку ≤ 1000 виїздів (spec §6, `docs/contracts/events.md`).
- Дедлайн 2026-10-26: найменше коду й один маршрут.

## Considered options

1. **Усе в сторінці, нативний `<details>` без JS** — кожен виїзд є `<details>`, звіт вбудований у HTML, список — елементи `<details>`, а не `<table>`.
2. **JSON-ендпоінт і підвантаження при розгортанні** — легша сторінка, звіт приходить запитом за `(mac, seq)` власним скриптом.

## Decision outcome

**Chosen:** варіант 1. Розгортання працює без скриптів, тож CSP лишається `default-src 'self'` без дозволу inline-скриптів, а в застосунку один маршрут і немає другого кінця для захисту. Ціна — вага сторінки росте з кількістю виїздів (до 1024 байтів на виїзд, тобто близько мегабайта при ≤ 1000); ця межа записана в SAD §7 і §11 і є причиною повернутися до варіанта 2, якщо обмеження таблиці (spec §8) не запровадять.

## Consequences

**Positive**
- Немає власного JS і другого ендпоінта; працює з вимкненими скриптами і з суворим CSP.
- Стан розгортання зберігає браузер; повторне натискання згортає рядок, інші лишаються як є.
- Звіти завжди відповідають тому самому знімку, що й підсумки (ADR-0001).

**Negative**
- Сторінка важчає лінійно: усі звіти завантажуються навіть якщо жоден не розгорнуто.
- Список з `<details>` не дає сортування й вирівнювання стовпців, як `<table>`; макет таблиці на широких екранах доведеться будувати стилями.

**Neutral**
- Перехід до підвантаження пізніше локальний: з'являються маршрут `GET /sessions/{mac}/{seq}` і невеликий скрипт, шаблон рядка лишається.
- Блоки з графіками (кроки 4–6) додають скрипт ECharts зі `static/`, тож CSP тоді доведеться розширити для цих сторінок; для цього екрана ні.
