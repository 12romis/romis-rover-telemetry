# Screens — dashboard-summary

> Канонічний **маніфест екранів** — кожен екран у кожному стані — створений `screens` (між `api` і `tasks`).
> Читають: `tasks` (кожна `ui`-задача цитує id SCR і стани), `implement` (будує екран за оголошеними
> станами) і `review` (зібраний екран має відповідати цьому файлу). Далі за ланцюжком посилаються
> **лише на цей маніфест**.

## Source

- **Tool:** code (з `docs/design-system.md`; Figma не авторизовано, Pencil MCP у сесії немає — це штатний режим канону, не деградація).
- **File:** «inline wireframes below» — вайрфрейми під кожним екраном; ширина вайрфрейма телефона ≈ 360 px.
- **Дані вайрфреймів:** значення рядків №26 і №27 взято з фікстур `tests/fixtures/session_seq26.json`, `session_seq27.json` (ровер `288485922c94` = «RomisRover», рішення власника №10). Час «отримано» та виїзд №28/№29 у станах `partial` і `gaps` — **ілюстративні** (у фікстурах їх немає).
- **Джерела станів:** spec §5 (AC-01…AC-18), `sad.md` §4, §6, §8 (503 при недоступному сховищі, «немає даних» як макрос, київський час, екранування), `ux-flows.md` (SCR-01, SCR-02, Flow US-01…US-10), контракт `docs/contracts/events.md` (nullable-поля). Контрактних кодів помилок немає: сторінка `GET`, помилку читання `sad.md` §6 зводить до одного стану `error`.

## Screens

### SCR-01 — Дашборд (опис, підсумки, виїзди)

Єдина сторінка (`GET /`). Складається з блоків зверху вниз: **Опис → Підсумки → Виїзди**. Стани екрана — це стани сторінки; розгорнутий рядок виїзду — окремий екран SCR-02.

| State | Trigger / condition | Components (from the inventory) | Source-ref |
|---|---|---|---|
| default | Сховище доступне, є ≥ 1 виїзд, значення відомі, пропусків немає (AC-01, AC-02, AC-03, AC-04, AC-09, AC-10, AC-17, AC-18). Згорнутий рядок виїзду — стан `collapsed` компонента «Рядок виїзду» | `base.html` (базовий макет); Картка показника (макрос) ×8; NEW: Рядок виїзду ×N | wireframe SCR-01 / default |

| gaps | Між першим збереженим і найновішим номером є номери без виїзду, втрачені або відхилені (AC-08, AC-16) | `base.html` (базовий макет); Картка показника (макрос); NEW: Рядок виїзду; NEW: Позначка пропуску | wireframe SCR-01 / gaps |

**Правила показу (діють для SCR-01 і SCR-02).** Усе — українською, простою мовою, без внутрішніх термінів і скорочень (`seq`, `mac`, `holds`, `failsafe`).

- **Три вигляди значення (AC-06, конституція №4).** Виміряний нуль → `0 м`, `0 с`, `0` — звичайним числом. Число → число з одиницею. Не передано (`NULL`) → слова «немає даних» макросом «Порожній стан «немає даних»»: курсив, приглушений колір з окремої ролі токенів і сам текст, тож вигляд відрізняється від числа не лише кольором. Жодних прочерків, порожніх клітинок, `—` чи `0` замість відсутнього.
- **Підсумок-сума (AC-07).** Сума лише за виїздами з даними; якщо ≥ 1 виїзд без даних — під значенням підпис «без даних у N з M виїздів»; якщо даних немає в жодному — значення «немає даних» (не 0), підпису немає. Правило однакове для пробігу, часу руху й утримань (`Total(sum, missing)`, `sad.md` §8).
- **Одиниці.** Пробіг: `distance_cm` → метри з комою, до двох знаків (`17` → `0,17 м`, `0` → `0 м`). Тривалість і час руху: `*_ms` → `4,3 с`; від 60 с — `3 хв 7 с`; від 60 хв — `1 год 2 хв`. Напруга: `*_mv` → вольти з двома знаками (`7691` → `7,69 В`). Десятковий розділювач — кома.
- **Час (AC-09, конституція №5).** Лише `received_at`, формат `ДД.ММ.РРРР ГГ:ХВ`, пояс Europe/Kyiv; підпис завжди «Отримано (за київським часом)» — у підсумку й у кожному рядку. Слів «час виїзду», «час сесії» немає ніде.
- **Причина завершення (AC-04).** `disarm` → «Роззброєння»; `failsafe_link_lost` → «Зникнення зв'язку з пультом»; `failsafe_voltage` → «Занизька напруга акумулятора»; інше значення → «Інша причина» (справжнє значення видно в SCR-02); `NULL` → «немає даних» (це не «інша причина»).
- **Ровер.** `288485922c94` → «RomisRover» (рішення власника №10); решта ровери — 12-символьний ідентифікатор плати як є.
- **Текст зі звіту** (ровер, прошивка, причина) виводиться лише як екранований текст (spec §6.1, `sad.md` §8).
- **Порядок.** Рядки й позначки йдуть за номером виїзду від більшого до меншого, потім за ровером; час «отримано» порядок не змінює (AC-03, AC-09).

**Копія блоку «Опис» (AC-02), вона ж зразок для `implement`:**

> **Телеметрія ровера.** Це дашборд ровера — невеликої машини на колесах, яку керують з пульта. Виїзд — один запуск ровера: від увімкнення моторів до зупинки. Утримання — коли ровер зупиняється перед перешкодою, доки вона не зникне. Ровер не знає часу, тому ми показуємо, коли звіт отримано.

**Підсумки — вісім карток у порядку AC-01** (під заголовком «Підсумки за всі виїзди»):

| # | Підпис картки | Значення | Підпис під значенням |
|---|---|---|---|
| 1 | Виїздів | кількість збережених виїздів | — |
| 2 | Пробіг | сума, м | «без даних у N з M виїздів» за правилом вище |
| 3 | Час руху | сума, с/хв | те саме |
| 4 | Утримань перед перешкодою | сума `holds.count` | те саме |
| 5 | Кінцева напруга останнього виїзду | `voltage_end_mv` виїзду з найбільшим номером, В; без підміни попереднім, якщо її немає | «виїзд № N» |
| 6 | Отримано востаннє (за київським часом) | найпізніше `received_at` | — |
| 7 | Прошивка останнього виїзду | `fw.version` виїзду з найбільшим номером | — |
| 8 | Втрачені сесії | кількість номерів без виїзду | — |

**Рядок виїзду** (компонент «Рядок виїзду», стан `collapsed`): шапка «Назва ровера · Виїзд № N» зі стрілкою ▸; далі пари «підпис — значення»: Отримано (за київським часом), Причина завершення, Тривалість, Час руху, Пробіг, Утримань, Напруга на початку, Мінімальна напруга, Напруга наприкінці, Прошивка (AC-03).

**Позначка пропуску** (компонент «Позначка пропуску», AC-08, AC-16): нерозгортуваний рядок штриховою рамкою, текст «Назва ровера · № N — виїзду з цим номером немає»; по одній позначці на кожен номер, на його місці в порядку рядків; однакова для втраченого й відхиленого номера.

**Розкладка.**

- **Телефон (від 360 px, базовий макет):** одна колонка; картки підсумків у 2 колонки, картки 4 і 5 на всю ширину (довгі підписи); рядок виїзду — картка на всю ширину; поля рядка — пари «підпис — значення» в 2 колонки, довгі значення переносяться всередині картки (`overflow-wrap`), сторінка вбік не прокручується (AC-10).
- **Широкий екран (від 640 px — припущення OP-1):** той самий макет, лише більше колонок: підсумки у 4 колонки, поля рядка в 4 колонки; контент обмежено по ширині й центровано. Окремих флоу немає.
- **Ціль дотику:** шапка рядка виїзду має висоту ≥ 44 px на всю ширину рядка (припущення OP-2).

### SCR-02 — Звіт виїзду (розгорнутий рядок)

Не окрема сторінка й не модальне вікно: це розгорнутий стан рядка виїзду з SCR-01 (нативний `<details>` без скриптів, ADR-0002). Звіт уже міститься в сторінці, тож жодного запиту при розгортанні немає. Шапка рядка лишається на місці, стрілка змінюється на ▾; під полями рядка з'являється блок звіту. Решта рядків лишається згорнутою; розгортання одного не згортає інші; повторне натискання на шапку згортає рядок (`ux-flows.md` §Platform decisions).

**Рішення власника (інтерв'ю screens): повний звіт — форматований JSON цілком**, як зберігає сховище (`payload`), екранований як текст. Підпис над блоком: «Звіт так, як його надіслав ровер». Поле зі значенням `null` лишається `null` (не нуль і не «немає даних»); поле, якого ровер не передав, відсутнє в JSON (AC-06). Невідомі поля звіту з'являються самі (конституція №8). Рядки переносяться всередині блоку (`white-space: pre-wrap`, `overflow-wrap: anywhere`), сторінка вбік не прокручується (AC-10). Порядок ключів у блоці — порядок, у якому їх віддає Postgres `jsonb`, а не обов'язково ровера (OP-3).

## New components

| Component | Why no existing primitive fits | Registered in design-system |

## Open points

Припущення цього етапу; джерела в контракті чи рішеннях власника для них немає (конституція №3). Дії за замовчуванням уже закладені в маніфест. Останнє питання spec §8 («Точні підписи, порядок підсумків і розкладка на вузькому екрані?») закрито цим файлом.

- **OP-1.** Єдина точка переходу до широкої розкладки — `min-width: 640px`; після `implement` значення записується в `docs/design-system.md` §Platform posture. Default now: 640 px. — owner: 12romis, due: до `/sdd:implement`.
- **OP-2.** Мінімальна ціль дотику шапки рядка — 44 px (орієнтир WCAG 2.5.5 і HIG, не з вимог проєкту). Default now: 44 px. — owner: 12romis, due: до `/sdd:implement`.
- **OP-3.** Порядок ключів у блоці звіту визначає `jsonb` (за довжиною, потім за алфавітом), не ровер; байтово точний звіт (`raw`) ADR-0001 не читає. Default now: показувати з `payload` у порядку `jsonb`. — owner: 12romis, due: після презентації 2026-10-26.
- **OP-4.** Точні тексти опису, підписів карток і причин узяті з цього файлу; власник може змінити будь-який без перегляду структури. Default now: тексти цього файлу. — owner: 12romis, due: до `/sdd:ship`.
- **OP-5.** Формат часу «отримано» — `ДД.ММ.РРРР ГГ:ХВ` (без секунд). Default now: без секунд. — owner: 12romis, due: до `/sdd:ship`.
