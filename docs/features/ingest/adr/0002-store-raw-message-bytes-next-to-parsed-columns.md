# 0002 — Зберігати точні байти повідомлення поруч із розібраними колонками

- **Status:** Accepted
- **Date:** 2026-10-23
- **Deciders:** 12romis (власник), Claude (design)

## Context

Фундаментальний ADR-0003 (`docs/adr/`) визначив для `sessions` розібрані колонки та `payload jsonb`. AC-12 вимагає зберегти початковий вміст звіту «дослівно, без перетворень», а AC-05 і AC-07 — зберігати вміст відхилених повідомлень (сміття може бути не UTF-8). `jsonb` нормалізує вміст: міняє порядок ключів, прибирає пробіли та дублікати ключів. Додати колонку пізніше можна лише для нових рядків, а вже прийняті звіти не відновити, тому рішення практично незворотне (SAD §5, data-model).

## Decision drivers

- Конституція №8: повний сирий JSON зберігається поруч із розібраними колонками.
- AC-12: невідомі поля зберігаються дослівно; AC-05, AC-07: вміст відхилених зберігається дослівно в межах 1024 байт, понад ліміт обрізається по байтах.
- Звіт, якого немає у сховищі, не відновлюється (ровер стирає його після підтвердження).
- Тип `text` не вміщує нуль-байтів і невалідного UTF-8.

## Considered options

1. **`raw bytea` + розібрані колонки + `payload jsonb`** у `sessions`; `raw bytea` + `raw_truncated` + `raw_size` у `rejected`.
2. **Лише розібрані колонки та `payload jsonb`** (як у фундаментальному ADR-0003), `raw` лише для відхилених.
3. **`raw text`** замість `bytea`.

## Decision outcome

**Chosen:** варіант 1. Для валідного звіту `raw` — точні байти повідомлення (за AC-05 не більше 1024, тож без обрізання); `payload jsonb` лишається для запитів і представлень. Для відхиленого `raw` — перші 1024 байти, `raw_size` — початковий розмір, `raw_truncated` — позначка обрізання (до ліміту не входить). Варіант 2 дає лише семантичну еквівалентність, варіант 3 губить повідомлення, що не є валідним UTF-8.

## Consequences

**Positive**
- Дослівність справжня, а не «за значенням»; одна форма в `sessions` і `rejected`.
- Майбутній перерозбір відхилених (зараз non-goal, spec §3) і відновлення колонок із початкових байтів лишаються можливими.

**Negative**
- До 1 КБ зайвих даних на сесію; при кількох звітах на день це невагомо.
- Дві копії вмісту (`raw`, `payload`) можуть розійтися, якщо код запису помилиться; тест на фікстурах перевіряє, що `payload` = розбір `raw`.

**Neutral**
- Доповнює фундаментальний ADR-0003, а не скасовує його: колонки й `payload jsonb` лишаються.
