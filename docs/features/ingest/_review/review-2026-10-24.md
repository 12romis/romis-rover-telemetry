### F1 — [stage-1, blocking] «Отруйні» повідомлення зациклюють ingest
- Де: `src/rover_telemetry/domain/report.py:169-189`, `src/rover_telemetry/ingest/__main__.py:80-84`. AC-05, конституція №7, spec §6.1.
- Проблема: NaN/Infinity, `seq`/`duration_ms` ≥ 2^31, `\u0000` у рядках, одиночний сурогат проходять `parse_report`, але Postgres їх відхиляє → вихід без ack → повторна доставка без кінця, черга стопориться.
- Пропозиція: `parse_constant` у `json.loads`; межі int32 для `_INT`; перевірка рядків/ключів на `\x00` і сурогати; запобіжник у `handle_message` (`psycopg.DataError` → rollback → `insert_rejected` → commit → ack); тести на кожен випадок.
- **Вердикт: Fix now** (рішення власника 2026-10-24) — повернути в `/sdd:implement ingest`.
