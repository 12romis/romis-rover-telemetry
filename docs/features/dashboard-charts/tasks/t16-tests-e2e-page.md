# T16 — Додати наскрізні браузерні тести сторінки: 360 px, дотик, 0 сторонніх запитів, CSP, збій кожного блока, XSS-фікстура

## Why (user story)

> **As a** Глядач
> **I want** переглядати графіки на телефоні без прокручування вбік і дізнаватися значення дотиком
> **So that** презентацію можна показати з будь-якого пристрою
>
> — `spec.md §4, US-09, verbatim` · full text: [spec.md](../spec.md)

> **As a** Оператор сервера
> **I want** щоб блоки з графіками лише читали збережені дані, не залежали від сторонніх вузлів і щоб збій одного блоку не ламав сторінку чи збереження звітів
> **So that** дашборд можна безпечно показувати публічно, а ровер не втрачав звіти
>
> — `spec.md §4, US-10, verbatim` · full text: [spec.md](../spec.md)

Цей крок перевіряє в реальному браузері вимоги, яких не бачать юніт-тести: телефонну ширину, дотик, мережу, CSP і незалежність блоків.

## Inlined context

> Затримка формування даних для графіків (p95) ≤ 1 с при ≤ 1000 збережених виїздів — інтеграційний тест на згенерованих даних.
> Актуальність: новий збережений виїзд видно на графіках при першому оновленні сторінки (кешування даних — 0 с) — тест AC-22 на реальному сховищі.
> Зовнішні залежності: 0 запитів до сторонніх вузлів — перегляд мережевих запитів сторінки в тесті.
> Придатність на телефоні: немає горизонтального прокручування при ширині екрана від 360 px; натискні елементи ≥ 44 px.
> Ізоляція блоків: 0 збоїв решти сторінки за збою одного блоку (3 з 3 незалежні) — тест AC-19.
>
> — `spec.md §6, NFR rows, abridged` · full text: [spec.md](../spec.md)

> Текст зі звіту (назва датчика, причина завершення, прошивка) у підказках графіка — вставка розмітки — Mitigation: `|tojson` для даних, словник підписів на сервері, невідоме значення лише як `textContent`; тест із фікстурою, де поля містять `</script>` і `<img onerror=…>`.
>
> — `sad.md §11, Risks (рядок 3), verbatim` · full text: [sad.md](../sad.md)

> Заголовок `Content-Security-Policy: default-src 'self'` лишається без змін: ні inline-скриптів, ні стилів, ні сторонніх вузлів (`web/app.py`, spec §6.1 «політика захисту не послаблена», AC-21).
>
> — `sad.md §2, Technical constraints, abridged` · full text: [sad.md](../sad.md)

> Збій побудови блоку — `try/except` на межі `web` для кожного блоку окремо, повідомлення «графік недоступний» на його місці. Збій у браузері — окремо для кожного блоку в `charts.js`; без скрипта — те саме повідомлення
>
> — `sad.md §8, Error handling, abridged` · full text: [sad.md](../sad.md)

## Acceptance criteria

### AC-18 — happy path

> **Given** Глядач відкриває дашборд на екрані телефона
> **When** сторінка завантажилась
> **Then** кожен графік вміщується в ширину екрана без прокручування сторінки вбік, підписи читаються, а значення виїзду з'являється дотиком до його місця на графіку, а не лише наведенням курсора
>
> — `spec.md §5, AC-18, verbatim` · full text: [spec.md](../spec.md)

### AC-19 — error

> **Given** один із блоків не вдалося побудувати
> **When** Глядач відкриває дашборд
> **Then** на місці цього блоку є повідомлення простою мовою, що графік недоступний, без технічних подробиць, а опис, підсумки, таблиця та інші блоки працюють
>
> — `spec.md §5, AC-19, verbatim` · full text: [spec.md](../spec.md)

### AC-21 — happy path

> **Given** Оператор сервера опублікував дашборд із графіками
> **When** Глядач відкриває публічну адресу
> **Then** сторінка з графіками відкривається через захищене з'єднання, працює без звернень до сторонніх вузлів, а збереження нових звітів триває, навіть якщо дашборд зупинено
>
> — `spec.md §5, AC-21, verbatim` · full text: [spec.md](../spec.md)

## Edge cases

| Case | Behaviour |
|---|---|
| Chromium не встановлено | e2e пропущено; `pytest -m 'not integration'` зелений |
| Збій двох блоків одночасно | обидва замінені повідомленням; третій і решта сторінки працюють |
| Жодного виїзду | три блоки `empty`, горизонтального прокручування немає |
| Дотик по слоту «не дійшла» | підказки немає, помилки консолі немає |
