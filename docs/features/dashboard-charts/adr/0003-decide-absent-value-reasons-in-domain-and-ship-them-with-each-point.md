# 0003 — Вирішувати причини відсутності значення в domain і передавати їх разом із точкою

- **Status:** Accepted
- **Date:** 2026-10-24
- **Deciders:** 12romis (власник), Claude (design)

## Context

Графіки мають відрізняти виміряний нуль, «немає даних» і конкретні причини: «не їхав», «на борту не було енкодера», «прямої ділянки не було», «утримань не було», захист від перешкод вимкнено (конституція №4, spec AC-03, AC-08, AC-09, AC-12, AC-13). ECharts розуміє лише число або пропуск; причини потрібні в підказках і підписах. Правила виведення причин — бізнес-логіка з контракту (`moving_ms`, `encoders.*`, `speed.imbalance_pct`, `holds.*`, `tof_control_off_ms`). Ризик №1 з `docs/idea-brief.md`: `null`, перетворений на 0 у SQL чи ECharts, покаже «швидкість 0» замість «немає даних».

## Decision drivers

- 0 випадків, коли «немає даних» чи «утримань не було» показано числом або точкою на нулі (spec §6 «Коректність відсутніх значень»).
- Правила перевіряються `pytest` на фікстурах seq 26/27 і реальних сесіях 36–39 без браузера (конституція №15).
- Правило живе в одному місці, а не розповзається між Python і JS (фундаментальний ADR-0002: чистий `domain`).
- Причини не змішуються між собою (AC-12).

## Considered options

1. **`domain/charts.py` вирішує й передає** — кожне значення точки — `Value(число)` або `Absent(reason)`, де `reason` — елемент `AbsentReason` (`NOT_MOVING`, `NO_ENCODER` із зазначенням борту, `NO_STRAIGHT`, `NO_HOLDS`, `NOT_REPORTED`); `web/formatting.py` додає підпис простою мовою (як уже робить `end_reason_label`); у JSON точка має `null` у значенні плюс код і підпис причини; `charts.js` лише показує.
2. **JS виводить причину з сирих полів** — сервер віддає `moving_ms`, `encoders_*`, `speed_*`, `holds_*`, а `charts.js` вирішує, що показати.

## Decision outcome

**Chosen:** варіант 1. Усі правила `null` ≠ 0 і причин тестуються швидкими юніт-тестами `domain`, а `charts.js` лишається «німим» шаром малювання. Пріоритет причин для відсутньої швидкості (початкове рішення design, у контракті порядку немає): не їхав → без енкодера (із зазначенням борту) → прямої ділянки не було (лише для різниці бортів) → не передано; позначка «без енкодера» (AC-13) не залежить від цього порядку. Перевірка порядку на фікстурах і реальних сесіях — `plan-tests`. Варіант 2 дублює бізнес-правила у двох мовах, не покривається `pytest` і дозволяє `null` непомітно стати 0 на межі ECharts.

## Consequences

**Positive**
- Правила достовірності відсутнього перевіряються без браузера й Docker.
- `charts.js` не містить чисел і правил: менше місць для помилки «`null` як нуль».
- Зміна порядку причин — одна функція `domain`.

**Negative**
- `domain/charts.py` і `web/formatting.py` мають узгоджено знати набір `AbsentReason` (підпис додає `web`): нова причина змінює обидва файли, це покриває тест на повноту словника.
- Дані точки важчі: поруч із числом їде код причини й підпис.
- Початковий пріоритет причин — припущення design (SAD §11).

**Neutral**
- Той самий модуль можна перевикористати в кроці 8 (інші графіки) для нових причин.
